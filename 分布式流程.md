## TinyZero 分布式流程详解（完整版）

---

### 一、整体架构概览

TinyZero 的分布式训练采用 **Ray + NCCL** 的双层架构：

| 层级 | 技术 | 职责 |
|------|------|------|
| **调度层** | Ray | 进程管理、资源分配、远程方法调用（RPC） |
| **通信层** | NCCL（通过 `torch.distributed`） | GPU 之间的高性能集合通信（allreduce、allgather 等） |

系统中有三种"进程角色"：

| 进程角色 | 运行位置 | 职责 |
|----------|----------|------|
| **主进程（Driver）** | CPU | 编排调度、数据分发、结果收集 |
| **远程 Worker 进程** | GPU（每张 GPU 一个进程） | 实际的模型计算 |
| **Register Center** | CPU（轻量级 Ray Named Actor） | 中转 rank 0 生成的通信地址 |

PPO 训练涉及的逻辑角色：

| 角色 | Worker 类 | 职责 |
|------|-----------|------|
| Actor + Rollout | `ActorRolloutRefWorker` | 策略模型的训练和推理采样 |
| Critic | `CriticWorker` | 价值函数的训练和推理 |
| Reference Policy | `ActorRolloutRefWorker` | 参考策略（冻结，用于计算 KL 散度） |

### 六、远程进程的初始化（最核心的部分）

当 `ray_cls_with_init(...)` 调用 `.remote()` 后，Ray 在远程 GPU 进程中实例化 `WorkerDict`。Python 的对象创建机制是**先 `__new__` 后 `__init__`**。

#### 6.1 `Worker.__new__` — 对象创建阶段

```85:100:e:\TinyZero\verl\single_controller\base\worker.py
    def __new__(cls, *args, **kwargs):
        instance = super().__new__(cls)

        disable_worker_init = int(os.environ.get('DISABLE_WORKER_INIT', 0))
        if disable_worker_init:
            return instance  # 直接返回，跳过后续配置

        rank = os.environ.get("RANK", None)
        worker_group_prefix = os.environ.get("WG_PREFIX", None)

        if None not in [rank, worker_group_prefix] and 'ActorClass(' not in cls.__name__:
            instance._configure_before_init(f"{worker_group_prefix}_register_center", int(rank))

        return instance
```

**`__new__` 的作用：** 在 `__init__` 之前执行前置配置。对于 rank 0，它会生成 `MASTER_ADDR` 和 `MASTER_PORT`：

```102:117:e:\TinyZero\verl\single_controller\base\worker.py
    def _configure_before_init(self, register_center_name: str, rank: int):
        if rank == 0:
            master_addr, master_port = self.get_availale_master_addr_port()
            rank_zero_info = {
                "MASTER_ADDR": master_addr,
                "MASTER_PORT": master_port,
            }
            # 注册到 Ray Named Actor (Register Center)
            self.register_center = create_worker_group_register_center(
                name=register_center_name, info=rank_zero_info)
            # 写入当前进程的环境变量
            os.environ.update(rank_zero_info)
```

**为什么要用 `__new__` 而不是 `__init__`？** 因为 `Worker.__init__` 中需要读取 `MASTER_ADDR` 和 `MASTER_PORT` 环境变量，如果在 `__init__` 中才生成就来不及了。`__new__` 在 `__init__` 之前执行，可以提前准备好这些环境变量。

### 七、NCCL 通信组的建立（跨进程 + 进程内）

这是分布式通信的核心。分两个维度理解：

#### 7.1 跨进程维度：所有 GPU 进程汇合

`torch.distributed.init_process_group(backend="nccl")` 是一个**阻塞调用**。它从环境变量中读取 `MASTER_ADDR`、`MASTER_PORT`、`RANK`、`WORLD_SIZE`，然后连接到汇合点，**等待所有进程都到齐**后才返回。

假设 4 张 GPU（`WORLD_SIZE=4`）：

```
GPU 0 进程: init_process_group("nccl") → 连接到 MASTER_ADDR:PORT → 等待...
GPU 1 进程: init_process_group("nccl") → 连接到 MASTER_ADDR:PORT → 等待...
GPU 2 进程: init_process_group("nccl") → 连接到 MASTER_ADDR:PORT → 等待...
GPU 3 进程: init_process_group("nccl") → 连接到 MASTER_ADDR:PORT → 到齐！
                                                                     ↓
                                                              所有进程同时从阻塞中返回
                                                              NCCL 通信组建立完成 ?
```

这 4 个进程是由 Ray **并行**创建的（`.remote()` 是异步的），所以它们几乎同时进入 `init_process_group`，互相等待。

**`MASTER_ADDR:MASTER_PORT` 相同的进程才能加入同一个通信组。** 不同的 `RayWorkerGroup`（如非共址场景下的 actor 组和 critic 组）会有各自不同的地址，形成独立的通信组。

#### 7.2 进程内维度：共址角色共享通信组

在同一个 GPU 进程内，多个角色的 `__init__` 是**依次执行**的：

```
同一个 GPU 进程内部（以 GPU 0 为例）：

ActorRolloutRefWorker.__init__()
  → torch.distributed.is_initialized() 返回 False
  → 调用 init_process_group("nccl")
  → 成功加入通信组
  → 进程内部状态标记为"已初始化"

CriticWorker.__init__()
  → torch.distributed.is_initialized() 返回 True（同一个进程已经初始化过了）
  → 跳过 init_process_group
  → 直接使用已有的通信组

ActorRolloutRefWorker(ref).__init__()
  → torch.distributed.is_initialized() 返回 True
  → 跳过
```

**`is_initialized()` 是进程级别的状态检查**，它只看"我这个进程有没有调用过 `init_process_group`"，不涉及跨进程的检查。PyTorch 不允许同一个进程重复初始化默认进程组，所以 `if not is_initialized()` 是一个**防重复初始化的保护**。

#### 7.3 通信地址的传递链路

```
rank 0 远程进程                    主进程 (Driver)                  rank 1/2/3 远程进程
────────────────                  ────────────────                 ──────────────────
Worker.__new__()
  │
  ├─ 生成 MASTER_ADDR:PORT
  │
  ├─ 注册到 Register Center ──→  从 Register Center 获取
  │   (Ray Named Actor)          self._master_addr = ...  ──→  通过 env_vars 传入
  │                               self._master_port = ...       os.environ['MASTER_ADDR']
  └─ os.environ.update(...)                                     os.environ['MASTER_PORT']
```

### 八、spawn 创建独立视图

```649:649:e:\TinyZero\verl\trainer\ppo\ray_trainer.py
            spawn_wg = wg_dict.spawn(prefix_set=class_dict.keys())
```

`spawn` 为每个角色创建一个独立的 `RayWorkerGroup` "视图"，去掉方法前缀：

```
wg_dict (统一入口，带前缀)              spawn 后 (独立视图，无前缀)
──────────────────────────             ──────────────────────────
actor_rollout__generate_sequences      → actor_rollout_wg.generate_sequences
actor_rollout__update_actor            → actor_rollout_wg.update_actor
critic__compute_values                 → critic_wg.compute_values
critic__init_model                     → critic_wg.init_model
ref__compute_ref_log_prob              → ref_wg.compute_ref_log_prob
```

所有视图底层指向**同一组 Ray Actor 实例**。这是代理模式（Proxy Pattern）的应用，让共址部署的 worker 使用体验与独立部署完全一致。

### 十二、关键设计思想总结

| 设计 | 目的 | 位置 |
|------|------|------|
| **`Worker.__new__`** | 在 `__init__` 之前设置 MASTER_ADDR/PORT 环境变量，因为 `__init__` 中需要读取它们 | `worker.py:85` |
| **Register Center** | rank 0 生成地址后，通过 Ray Named Actor 中转给主进程，再分发给其他 rank | `worker.py:114` |
| **`DISABLE_WORKER_INIT`** | 共址时，子 worker 不需要重复执行 `_configure_before_init`（避免重复生成/注册地址） | `base.py:470` |
| **`if not is_initialized()`** | 同一进程中多个角色共享一个 NCCL 通信组，防止重复调用 `init_process_group` 报错 | `fsdp_workers.py:57` |
| **`init_process_group` 阻塞等待** | 所有 GPU 进程必须都到齐才能建立通信组，这是一个跨进程的汇合过程 | `fsdp_workers.py:58` |
| **Placement Group** | Ray 层面控制哪些 worker 放在哪些 GPU 上 | `base.py:221` |
| **`WorkerDict` + `spawn`** | 共址部署的多角色对外暴露与独立部署一致的 API（代理模式） | `base.py:461`, `ray_trainer.py:649` |
| **`RayClassWithInitArgs`** | 延迟实例化：先打包类和参数，等资源分配好后再 `.remote()` 创建 | `base.py:129` |



### 十三、IP地址获取

#### MASTER_ADDR 和 MASTER_PORT 的完整传递链路

#### 1. 生成地址（rank 0 远程进程中）

rank 0 的远程进程在 `Worker.__new__` → `_configure_before_init` 中生成通信地址：

```python
# worker.py 第 105-109 行
if rank == 0:
    master_addr, master_port = self.get_availale_master_addr_port()
    # _get_node_ip()   → 获取当前节点 IP（优先环境变量，否则 Ray SDK）
    # _get_free_port() → 绑定端口 0，让操作系统分配空闲端口
```

#### 2. 注册到 Register Center（rank 0 远程进程中）

生成后立即创建一个 Ray Named Actor 来存储地址：

```python
# worker.py 第 113-115 行
from verl.single_controller.base.register_center.ray import create_worker_group_register_center
self.register_center = create_worker_group_register_center(
    name=register_center_name,   # "{WG_PREFIX}_register_center"
    info=rank_zero_info)         # {'MASTER_ADDR': ..., 'MASTER_PORT': ...}
```

`create_worker_group_register_center` 的实现：

```python
# register_center/ray.py 第 28-29 行
def create_worker_group_register_center(name, info):
    return WorkerGroupRegisterCenter.options(name=name).remote(info)
```

`WorkerGroupRegisterCenter` 是一个简单的 Ray Actor，只存储和返回地址：

```python
# register_center/ray.py 第 18-25 行
@ray.remote
class WorkerGroupRegisterCenter:
    def __init__(self, rank_zero_info):
        self.rank_zero_info = rank_zero_info

    def get_rank_zero_info(self):
        return self.rank_zero_info
```

#### 3. 名字如何对应上

两边通过**同一个名字**关联。主进程在创建 worker 时通过 `env_vars` 设置 `WG_PREFIX`：

```python
# base.py 第 240 行（主进程设置）
env_vars = { 'WG_PREFIX': self.name_prefix, ... }
```

rank 0 远程进程从环境变量读取：

```python
# worker.py 第 94、98 行（远程进程读取）
worker_group_prefix = os.environ.get("WG_PREFIX", None)
instance._configure_before_init(f"{worker_group_prefix}_register_center", int(rank))
```

主进程用同一个前缀查找：

```python
# base.py 第 275 行（主进程查找）
register_center_actor = ray.get_actor(f"{self.name_prefix}_register_center")
```

`self.name_prefix` 默认是一个 6 位随机字符串（第 189 行），确保不同 WorkerGroup 的 Register Center 不会冲突。

#### 4. 主进程轮询等待并获取（`.remote()` 是异步的）

`.remote()` 是异步非阻塞的——主进程提交创建 Actor 的请求后**立即返回**句柄，不等待远程进程的 `__init__` 完成。所以主进程需要轮询等待 Register Center 出现：

```python
# base.py 第 269-279 行（主进程中执行）
if rank == 0:
    register_center_actor = None
    for _ in range(120):                    # 最多等 120 秒
        if f"{self.name_prefix}_register_center" not in list_named_actors():
            time.sleep(1)                   # 每秒检查一次
        else:
            register_center_actor = ray.get_actor(f"{self.name_prefix}_register_center")
            break
    # 获取地址
    rank_zero_info = ray.get(register_center_actor.get_rank_zero_info.remote())
    self._master_addr, self._master_port = rank_zero_info['MASTER_ADDR'], rank_zero_info['MASTER_PORT']
```

#### 5. 分发给其他 rank

主进程拿到地址后，在后续循环中通过 `env_vars` 传给 rank 1, 2, 3...：

```python
# base.py 第 245-248 行
if rank != 0:
    env_vars['MASTER_ADDR'] = self._master_addr
    env_vars['MASTER_PORT'] = self._master_port
```

```
rank 0 远程进程                  Ray Named Actor                   主进程 (Driver)
──────────────                  ───────────────                   ──────────────

Worker.__new__()
  │
  ├─ 生成 addr, port
  │   (get_node_ip + get_free_port)
  │
  ├─ create_worker_group_        WorkerGroupRegisterCenter
  │  register_center(            ┌──────────────────────┐
  │    name="abc123_register...", │ rank_zero_info = {   │
  │    info={ADDR, PORT}         │   MASTER_ADDR: ...,  │
  │  ) ────────────────────────→ │   MASTER_PORT: ...   │
  │                              │ }                    │

  │                              │   → return info      │ ←──── ray.get_actor(name)
```

**本质：** Register Center 是一个中间人——因为主进程和远程进程无法直接共享变量，通过 Ray Named Actor 传递通信地址，配合轮询等待解决异步创建的时序问题。
